Bugzilla Ticket Monitor

Paramètres de détection des nouveaux tickets

Connexion

Authentification

Votre profil Bugzilla → API Keys. Plus fiable que la session (pas besoin de garder un onglet ouvert).
Mode session : un onglet Bugzilla connecté doit rester ouvert dans ce profil. Les requêtes sont faites en même origine via un script de contenu (aucun problème de CORS) et votre session est réutilisée.

Polling

Critères de recherche (API REST)

Les critères sont combinés en ET logique. Séparez plusieurs valeurs par des virgules (logique OU).

Critères avancés (recherche avancée Bugzilla)

Champ / opérateur / valeur : permet d'utiliser les champs personnalisés (cf_*) et la recherche par historique.

Paramètres bruts (JSON, optionnel)

Permet d'utiliser n'importe quel paramètre de l'API REST non couvert ci-dessus.

Notifications

Guide rapide des champs
  • produit / component : nom exact du produit / composant Bugzilla.
  • status : NEW, ASSIGNED, REOPENED, RESOLVED… par défaut les statuts ouverts.
  • severity / priority : blocant, majeur, normal… / --, P1…P5.
  • assigned_to / creator / qa_contact : identifiant de connexion d'un utilisateur.
  • summary / whiteboard : sous-chaîne (recherche de sous-chaîne).
  • keywords / tags : mots-clés ou tags de l'entrée.
  • version / target_milestone : version ou jalon cible.
  • quicksearch : syntaxe de recherche rapide Bugzilla.
  • Critères avancés : ex. champ cf_periodic_check, opérateur equals, valeur oui.
